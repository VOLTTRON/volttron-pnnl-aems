# Docker

Docker Compose orchestration for the full Skeleton stack. Core services (client, server, services, seeders, init, database, backup) always run; optional services (redis, proxy, sso, map, nom, wiki) are gated behind **compose profiles**.

## Layout

- [docker-compose.yml](../../docker-compose.yml) — root **shim** that `include:`s [docker/docker-compose.yml](../../docker/docker-compose.yml) with `project_directory: ./docker/`.
- [docker/docker-compose.yml](../../docker/docker-compose.yml) — the real stack definition.
- [docker/database/](../../docker/database/) — custom Postgres image with PostGIS installed ([Dockerfile](../../docker/database/Dockerfile), [postgis.sh](../../docker/database/postgis.sh)). Vanilla `postgres:16` will not work.
- [docker/proxy/](../../docker/proxy/) — Traefik v3 dynamic config ([certs-traefik.yml](../../docker/proxy/certs-traefik.yml)). Terminates TLS, routes `/`, `/graphql`, `/api`, `/ext/*`, `/auth/sso/`.
- [docker/certs/](../../docker/certs/) — cert provisioning helper ([Dockerfile](../../docker/certs/Dockerfile), [mkcert.sh](../../docker/certs/mkcert.sh)). Runs before proxy.
- [docker/keycloak/](../../docker/keycloak/) — Keycloak image + [default-realm.json](../../docker/keycloak/default-realm.json) + [init-keycloak.sh](../../docker/keycloak/init-keycloak.sh).
- [docker/backup/](../../docker/backup/) — backup sidecar (Node worker that snapshots Postgres on a schedule).
- [docker/map/](../../docker/map/) — OSM tile server assets.
- [docker/wiki/](../../docker/wiki/) — BookStack wiki service assets.
- [docker/seed/](../../docker/seed/) — DB seed JSON.
- [docker/secrets/backup/](../../docker/secrets/) — host-side directory for the backup sidecar's auto-generated age keypair. Gitignored. The rest of `docker/secrets/` is legacy (Docker secrets removed; see [secrets model](#secrets-model)).

## Run from the repo root, not from `docker/`

The root [docker-compose.yml](../../docker-compose.yml) is a shim. **Always invoke `docker compose` from the repo root** so it auto-loads the root [.env](../../.env). Running compose from inside `docker/`, or with `-f docker/docker-compose.yml` from the root, makes compose look for `docker/.env` instead — which is **not** where the project's env vars live.

```bash
# CORRECT — picks up root .env and resolves build contexts correctly
docker compose up -d
docker compose --profile proxy --profile sso up -d

# WRONG — loads docker/.env; wrong variables
cd docker && docker compose up -d
docker compose -f docker/docker-compose.yml up -d
```

**Profile gating is load-bearing for minimal deploys** — don't strip `profiles: [...]` to "make it simpler."

## Traefik routing

| Path pattern | Destination | Notes |
|---|---|---|
| `/` (all other) | `skeleton-client:3000` | Next.js app |
| `/graphql`, `/api/*`, `/ext/*` | `skeleton-server:3000` | NestJS API |
| `/auth/sso/*` | `skeleton-keycloak:8080` | Keycloak — only with `sso` profile |

TLS terminates at Traefik. HTTP port 80 redirects to HTTPS port 443. mkcert certs are bind-mounted from `docker/certs/` (generated by `secrets.sh`).

## Secrets model

Plain env vars, single source. Real values live in [.env.secrets](../../.env.secrets) (gitignored). Compose interpolates `${VAR}` in the compose file from a project-root `.env` PLUS the files listed in `COMPOSE_ENV_FILES`. **Every `docker compose` invocation must have `COMPOSE_ENV_FILES=.env,.env.secrets` set** (either in the shell or via CLI `--env-file`) — the `include: env_file:` list is documentation only, it doesn't cascade to the outer file's interpolation. The wrapper scripts `start-services.sh` / `secrets.sh` export it automatically. Once interpolation resolves correctly, every service's `env_file: .env.<svc>` forwards `KEY=${KEY}` into the container, and native image conventions (postgres `POSTGRES_PASSWORD`, keycloak `KC_DB_PASSWORD`, MariaDB `MYSQL_ROOT_PASSWORD` / `MYSQL_PASSWORD`, grafana `GF_*`) pick them up directly.

The `server` and `services` containers receive `KEYCLOAK_ADMIN_PASSWORD` as a plain env var so `KeycloakAdminService` can authenticate against the master realm to manage realm roles on behalf of app users.

The backup sidecar's age-style encryption keypair is auto-generated on first boot into `./docker/secrets/backup/`, bind-mounted at `/host-secrets`. Unrelated to any Docker-secret machinery.

**Validation and rotation:**
- [check-env.sh](../../check-env.sh) / [check-env.ps1](../../check-env.ps1): validates that `.env.secrets` is complete and free of placeholders. Called automatically by `start-services.sh`.
- [secrets.sh](../../secrets.sh) / [secrets.ps1](../../secrets.ps1) — bootstrap `.env.secrets` on first run, migrate misplaced values from `.env`, and rotate live credentials. Detects a rotation by comparing the value in `.env.secrets` against the running container's env via `docker inspect`; on drift it runs the appropriate handler (`ALTER ROLE` for Postgres, `ALTER USER` for MariaDB, `kcadm` for Keycloak, `grafana-cli` for Grafana admin, restart for Redis/app-only secrets) then `docker compose up -d --no-deps <svc>` so the container inherits the new value. **`docker compose restart` reuses cached env and will NOT pick up new values** — always use `up -d --no-deps`. If a target container is down during rotation, the script refuses to proceed unless `--force` is set.

## Environment

- Root [.env](../../.env) — non-secret defaults + sentinel placeholders for secret keys. Auto-loaded by compose only when invoked from the repo root.
- Root [.env.secrets](../../.env.secrets) (gitignored, optional) — real secret values. Loaded by the root shim as an `env_file:` with `required: false`.
- `KEYCLOAK_ADMIN_INTERNAL_URL` — when set (e.g. `http://skeleton-keycloak:8080/auth/sso`), the `server` container routes Keycloak Admin REST API calls directly to the internal Docker DNS name, bypassing Traefik. Without this, the server would call out through the public hostname and back through the proxy unnecessarily. Typically set in `docker/.env.keycloak` or the root `.env`.
- Compose interpolates `${VAR}` from the shell. [start-services.sh](../../start-services.sh) / [start-services.ps1](../../start-services.ps1) load `.env` before invoking compose.
- `COMPOSE_PROJECT_NAME` prefixes container names — respect it when writing helper scripts.

## Networking

- Traefik terminates TLS at `:443` (and `:80` for redirect). Service containers do **not** expose host ports by default; they attach to the compose network and Traefik routes by Host/Path rule from container labels.
- The Traefik test dashboard is at `${TRAEFIK_TEST_PORT}` (when the `proxy` profile is active).
- `server.skeleton`, `client.skeleton`, etc. are internal DNS names within the compose network — used in the `REWRITE_*_URL` vars to keep traffic inside the network.

## Build context

Image builds for `client`, `server`, `prisma`, and `common` use the **repo root as build context** (`context: ../`), so they can pull in sibling portal-linked modules. The Dockerfiles live in each sub-project. **Don't change the build context** without understanding the portal dependency chain.

## Operational reference

| Action | Command |
|---|---|
| First-time setup | `./secrets.sh`, then `./check-env.sh`, then `docker compose up -d` |
| Rotate a credential | Edit `.env.secrets`, then `./secrets.sh` (detects the change, ALTERs the running DB, restarts affected services) |
| Rebuild after code change | `docker compose build <service>` or `--build` on `up` |
| Reset DB (⚠ destructive) | `docker compose down -v` |
| Tail logs | `docker compose logs -f <service>` |
| Exec into DB | `docker compose exec database psql -U ...` |
| Restart single service | `docker compose restart skeleton-server` |

## Database image

[docker/database/Dockerfile](../../docker/database/Dockerfile) extends the official Postgres 16 image with PostGIS 3. **Never substitute `postgres:16`** — the Prisma schema uses `Unsupported("geography(GEOMETRY,4326)")` columns that require PostGIS and would silently fail or error with the vanilla image.

## Gotchas

- **Secret files must exist before `up`** for any service that declares them. Ordering: `secrets.sh` → `check-env.sh` → `docker compose up`. Or use `start-services.sh` which runs the check automatically.
- **Running from `docker/`** → Wrong `.env` loaded; auth / hostname vars are wrong. Always run from repo root.
- **DB image is custom** — never replace with `postgres:16`; PostGIS will be missing.
- **Traefik v3 syntax** differs from v2. Check `traefik:v3.x` docs before copying older snippets.
- **Renaming a top-level secret** requires updating every `secrets: [...]` reference in each service.
- **The hostname in `.env` must be a real hostname** (not `localhost`) for OAuth + dev session sharing.
- **`docker compose down` (without `-v`) preserves volumes**; `down -v` wipes the DB.
- **Client `schema.graphql` not updating?** → `autoSchemaFile` only writes in non-production. Force-regen: `yarn compile:schema` in the server workspace.
- **Local client can't connect to Docker API?** → `REWRITE_*_URL` in `client/.env.local` must point to the real hostname, not `localhost`.
